# プロンプト設計

このドキュメントでは、3段パイプラインの Stage 1・Stage 3 で使用するプロンプトの設計方針と、Tool Use スキーマの構造を解説します。

---

## Stage 1: 特徴抽出プロンプト

### ペルソナ設計

```
あなたは冷静な解剖学的観察者です。
```

**意図:** 「似ている有名人は誰か」「美しいかどうか」という主観的判断に流れないよう、観察者ペルソナを明示する。LLM は指示がないと自然に評価・感情を交えた表現をしてしまうため、先手で制約する。

### 制約群

```
- 写真の人物を特定・推測してはいけません。
- 年齢・人種・民族・性別を断定的に語ってはいけません。
- 主観的な美醜評価をしてはいけません。形状の客観的観察のみ。
- 判断が曖昧な場合は、最も近い選択肢を選んでください。
```

**意図:**
- 「特定禁止」: 著名人の顔写真を使われた場合に本人と結びつけないため
- 「断定禁止」: 多様なユーザーに対して差別的・不快な出力を防ぐため
- 「曖昧な場合の指示」: Tool Use の enum は二択になれないため、強制的にどちらかを選ばせる

### 強度スコア

```
各カテゴリに加え、特徴の際立ち度を 1〜10 の整数で記録してください。
- 1 = 控えめ。他のカテゴリとの境界線上
- 5 = 平均的・標準的
- 10 = 際立って強く典型的
```

**意図:** 単純な enum 一致だけでなく、「どれだけ際立っているか」でスコアを調整する。例: 「アーモンド形の目で強度9」と「アーモンド形で強度3（ほぼ普通）」を区別してユーザーと歴史人物の類似度表示に深みを出す。

### Tool Use スキーマの設計

```typescript
{
  faceShape: { type: 'string', enum: [...FACE_SHAPES] },
  faceShapeIntensity: { type: 'integer', minimum: 1, maximum: 10 },
  // 8軸 × 2フィールド（カテゴリ + 強度）
  overallImpression: {
    type: 'array', items: { type: 'string' },
    minItems: 3, maxItems: 5,
  },
}
```

- **カテゴリと強度をペアにする**: 軸ごとに `*Intensity` を隣接させることで LLM が対応関係を把握しやすい
- **`overallImpression` を自由記述にする**: 8軸の enum では表現できない「全体的な印象」（例: `'stoic'`, `'intellectual'`）を自由タグで捕捉し、印象類似度（`impressionSimilarity()`）の計算に使う
- **`temperature: 0`**: 特徴抽出は創造性より一貫性が重要なため、温度を0に固定

## Stage 3: ナラティブ生成プロンプト

### ペルソナ設計

```
あなたは「歴史人物 魂マッチング診断」の語り部です。
落語家のような温かみと遊び心を持って...
```

**意図:** 「診断AIです」ではなく「語り部」とすることで、固い情報提供ではなく物語体の文章を引き出す。「落語家のような温かみと遊び心」という具体的なトーン指定で文体を方向付ける。

### 制約群

```
- reason には上位の一致特徴を必ず日本語で具体的に引用してください
  （例: 「鋭い顎のラインと深く落ち窪んだ目元」）。
- 写真の人物の年齢・人種・性別を断定的に語ってはいけません。
- 歴史的事実から逸脱した創作はしないでください。
```

**意図:**
- 「特徴の引用を必須にする」: `reason` が「この人物と似ています」という空虚な文にならないよう、具体的な特徴の言及を強制する。これにより診断の「根拠」が明示される
- 「歴史的事実の制約」: `episode` や `quote` でのハルシネーションを抑制する

### ユーザーメッセージの構造

Stage 3 に渡すユーザーメッセージは、Stage 2 の出力を構造化して渡す。

```
# 一致した歴史人物
織田信長 (戦国時代・日本, 1534-1582)
キーワード: 革新・決断力・カリスマ

# 上位の一致特徴
顎のライン: あなた=鋭角 / 人物=鋭角 (寄与10点)
頬骨: あなた=高い / 人物=際立つ (寄与8点)
...

# 印象タグ
あなた: stoic, intense, determined / 人物: fierce, visionary, ...
```

**意図:** Stage 3 は「何を語るか」を LLM に考えさせるのではなく、「与えられた事実をどう語るか」に集中させる。人物・特徴・印象タグを全て渡すことで、LLM が0から事実を生成するリスクを最小化する。

## Prompt Caching の境界

```
[キャッシュ対象] system prompt（固定テキスト）
                 ↑ cache_control: { type: 'ephemeral' }

[非キャッシュ]   ユーザーメッセージ（写真・特徴・人物情報）
                 ↑ リクエストごとにユニーク
```

詳細は [ADR-0006](adr/0006-prompt-caching.md) を参照。

---

## 設計上の反省点

- `overallImpression` は英語タグのみ（日本語と混在すると `impressionSimilarity()` の Jaccard 係数計算がずれる）
- Stage 1 の `temperature: 0` は一貫性を高めるが、曖昧な特徴に対して毎回同じ「間違い」を再現してしまうリスクもある
- `episode` と `quote` のハルシネーション検証は自動化しておらず、ランダムサンプルによる手動確認に依存している
